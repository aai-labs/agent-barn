# Startup

Use the context already loaded and the runtime's paths. Inspect the persistent work notes for unfinished commitments and applicable configured schedules when those interfaces are available.

Before resuming, check the current source state, authority, deadline and whether a previous write already succeeded. Continue only work with a still-valid mandate and an appropriate delivery route. If that cannot be established, preserve the work note and ask the relevant owner when communication is available.

Do not recreate schedules, resend old notifications or repeat onboarding merely because the runtime restarted. Send a recovery update only when a task's outcome, deadline or next action materially changed and sending that update is authorized.
